# F-002 - Write-Guardrail False Positive on Policy Documentation

- **Date:** 2026-09-26
- **Class:** Tooling / policy ergonomics (non-security failure)
- **Status:** Mitigated (pattern elision + operator write)

## What happened

Agent attempts to persist docs/handoff.md were denied by the write-time
credential guardrail in .pi/neurofebric-policy.json. The document describes the
policy itself, so it necessarily contains the policy's own field identifiers and
prose about the guardrail substrings - which the guardrail matches
case-insensitively anywhere in a write payload. Reads and searches are unaffected.

## Root cause

The guardrail scans write payloads for four substrings (spelled in the policy
file, intentionally not repeated here). Content that documents the guardrail
cannot avoid containing those substrings, so any agent write of such content is
denied. This is fail-closed behavior working as designed; the failure is
ergonomic, not a security gap.

## Accepted mitigations

1. Pattern elision: documents refer to .pi/neurofebric-policy.json instead of
   enumerating pattern tokens (adopted for docs/handoff.md).
2. Operator manual write: the policy gates agent writes; the human operator is
   outside that boundary.

Rejected: staging content in workspace/ and copying it via shell (cp/heredoc),
which routes the payload around write-time scanning. See enforcement gap below.

## Enforcement gap exposed (Phase 2 candidate)

Shell-mediated writes carry file content outside the write payload, so the
guardrail never sees it: `cp staged.md docs/x.md` or a bash heredoc persists
arbitrary content without a payload scan. Command text is still checked against
destructive and credential-access patterns, but content-level rules do not apply.
Candidate fixes: (a) detect redirection/heredoc write shapes in command text, or
(b) treat shell writes inside the workspace as write-tier payloads. Track
alongside REPORT.md priority 3 (structured policy-violation diagnostics naming
the matched pattern, so the model can self-correct in one retry).
